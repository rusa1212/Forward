## 2. 배경 및 문제 정의

### 2.1 기업 소개

현실의 산업 현장을 디지털 공간에 그대로 구현하고, 이를 지능적으로 운영하는 '에이전틱 디지털 트윈(Agentic Digital Twin)' 솔루션을 다루는 기업. 단순한 가상 공간 구현을 넘어, AI가 스스로 데이터를 분석하고 문제를 해결하는 미래형 산업 생태계를 구축하는 것을 지향.

### 2.2 문제 정의

- 국내 공공기관·정부부처(NTIS, IRIS, K-Startup, 나라장터 등)가 각각 **분산된 플랫폼**에서 R&D 공고를 게시
- 담당자가 여러 사이트를 개별적으로 방문해 확인해야 하며, **비효율적·반복적인 모니터링 업무** 발생
- 키워드 기반 자동 수집·알림 서비스 부재로 **적기 대응 기회 상실** 위험 존재

### 2.3 제안 내용

공공기관이 제공하는 Open API(NTIS, IRIS, K-Startup, 나라장터 등)를 연동하여, 사용자가 설정한 **키워드 기반으로 관련 공고를 자동 수집·검색**하고 신규 공고 발생 시 **알림을 발송**하는 웹 서비스 개발.

## 4. 프로젝트 범위

### 4.1 In-Scope (이번 프로젝트 범위)

- NTIS / 공공데이터포털 API 연동 (우선 순위 대상)
- API 미제공 사이트 대상 크롤링 샘플 1~2종 구현 (기술 검증 목적)
- 키워드/기관명/기간 검색 및 상세페이지 제공
- APScheduler 기반 주기적 수집 + 신규 공고 이메일 알림
- React SPA 프론트엔드 + FastAPI 백엔드 + PostgreSQL 배포 (Railway/Render/GitHub Pages 등 무료 티어)

### 4.2 Out-of-Scope (차기 단계로 이연)

- IRIS, K-Startup, 나라장터, RNDIP 등 전체 플랫폼 연동 (단계적 확대 예정)
- 카카오 등 알림 채널 다양화
- SaaS형 상용 서비스 전환 및 외부 기업 대상 배포

## 5. 주요 기능 명세

### F1. 데이터 수집 모듈

| 항목 | 내용 |
| --- | --- |
| 대상 | NTIS, 공공데이터포털 Open API / 크롤링 샘플 1~2종 |
| 수집 방식 | requests, BeautifulSoup 등 활용 |
| 수집 주기 | APScheduler 기반 스케줄링 (주기적 자동 수집) |
| 저장소 | PostgreSQL |

### F2. 키워드 검색·필터링

- 키워드 검색 (제목/본문 기반)
- 기관명 필터
- 공고 기간(시작~종료) 조건 검색
- 검색 결과 목록 + 상세 페이지 제공

### F3. 신규 공고 알림

- 스케줄러 기반 신규 공고 자동 감지
- 감지 시 등록 키워드와 매칭되는 사용자에게 이메일 발송

### F4. 웹 서비스

- **프론트엔드**: React 기반 SPA, UI/UX 설계 포함
- **백엔드**: FastAPI(Python) + PostgreSQL, REST API 설계
- **배포**: 클라우드 무료 티어 (Railway / Render / GitHub Pages 등)

### F5. 결과물 정리

- 최종 결과보고서
- 발표자료(PPT)

## 6. 시스템 아키텍처 (개요)

```
[공공 Open API / 크롤링 대상 사이트]
            │
            ▼
   [데이터 수집 모듈] ── APScheduler(주기 실행)
            │
            ▼
     [PostgreSQL DB]
            │
            ▼
   [FastAPI 백엔드] ── REST API ── [React 프론트엔드(SPA)]
            │
            ▼
     [이메일 알림 발송]
```
